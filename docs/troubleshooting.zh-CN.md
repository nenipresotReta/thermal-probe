# 首次启动与故障排查

[English](troubleshooting.md) | [简体中文](troubleshooting.zh-CN.md)

先按 [README](../README.zh-CN.md) 构建，并核对[接口表](interfaces.zh-CN.md)。仓库不含预配置固件；Wi-Fi 凭据在编译时嵌入，修改网络后需要重新构建和烧写。

## 首次验收

1. 上电前确认板型、供电、传感器端子和跳线导通。
2. 本地填写 `config/device.json`。执行 `sh build.sh`；配置缺失／无效必须阻止构建。用 `sh flash.sh` 烧写。
3. 从 LCD、USB 日志或路由器客户端列表取得 DHCP 地址，替换下面的 `DEVICE_IP`。
4. 连续有效采集约 10 秒后检查：

```sh
curl --fail --max-time 5 http://DEVICE_IP/api/temperature
python3 tools/check_wireless.py DEVICE_IP
```

应先看到 `valid: true`，再看到 `derivatives_ready: true`，温度为有限数且 `time_s` 前进。能读到数值不等于精度已验证，应在稳定温度下与已知参考比较。

5. Thermal Scope 中 DEVICE → TEST → CONNECT，检查数值和曲线持续更新。在探头额定范围内短暂改变温度，确认趋势跟随。

多客户端压力测试会占用连接并发送异常流量／测试超时，应安排独立测试，不在重要记录中运行。

## 分层排查

| 现象 | 优先检查 |
|---|---|
| 拒绝配置 | 模板、SSID 1–32 个 UTF-8 字节、WPA2 密码 8–63 字节，无控制字符 |
| 缺 SDK／编译器 | Zephyr 4.1.0、SDK 0.17.0 的 ESP32-S3 Xtensa 工具链、已激活 venv、Espressif blobs |
| 烧写连接失败 | 原生 USB 数据线／端口、关闭串口工具、BOOT + RESET |
| 没有 Wi-Fi 地址 | 2.4 GHz WPA2 凭据、信号、DHCP；此配置不支持开放／企业网络 |
| 路由器在线但 HTTP 不通 | 当前地址、路由、访客隔离、防火墙、供电；在线列表不保证 TCP 可达 |
| `valid: false` / SENSOR_ERROR | 供电共地、SPI 方向和脚位、PT100 导通、参考电阻、三线跳线 |
| 温度有效但导数无效 | 等待连续约 10 秒；传感器故障重置滤波 |
| HTTP 通但 Modbus 不通 | TCP 502、unit 1、功能码 3/4、零起始寄存器、大端 Float32 |
| 数值／比例错误 | PT100/PT1000、实际参考电阻、字序、单位；不要用偏置掩盖接线错误 |
| 偶发读数中断 | 区分重启、传感器无效、单客户端失败；关闭多余客户端 |
| 网络正常但屏幕空白 | 面板与总线是否匹配，ST7789 名称相同不能保证兼容 |

最多支持 4 个 Modbus、2 个 HTTP 客户端。Thermal Scope 多浏览器共享一个采集器；空闲测试连接会占用槽位直到超时。客户端超时不等于固件重启，应对照开机时间和重置日志。

## 问题反馈

提供提交／标签、准确板型和模块、供电、脚位、跳线导通、SDK／构建版本、轮询设置及简短脱敏错误。说明是否在没有额外测试客户端和串口工具时复现，并记录前后 valid／ready 状态与开机时间。

不要附真实配置、生成头文件、固件、完整构建目录或未经检查的日志。移除网络名称、密码、设备地址、MAC 和个人路径。

## 发布状态

初始固件仍为 RC。主机测试和短时实物压力测试不证明长期可靠性或其他板兼容性。早期掉线／无效响应观察尚未完全解释；已修复共享格式化并发问题，但没有捕获因果复现。报告时区分观察和已验证修复。
